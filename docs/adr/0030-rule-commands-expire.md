# ADR-0030：rule_add、rule_cancel 命令也会过期

- **状态**：已定
- **日期**：2026-11-14
- **来源**：M4 审查修复合并进 M6 时提出（2026-11-14 你的决定：选 C，两个都过期）；补充 M4 审查第 7 条（place / cancel 过期）

## 决策

命令行等待超时后，常驻进程才取出的 `rule_add`、`rule_cancel` 还要不要执行

## 取值

- `rule_add`、`rule_cancel` 和 `place`、`cancel` 一样带 `expires_at`（入队时间 + 命令行等待时间）；过了截止时间才被取出的，不交给规则引擎，结果为 `{"allowed": false, "rule": "expired"}`（`rule_cancel` 另带 `rule_id`）
- `halt`、`resume` 不过期：halt 只会减少风险，晚执行也比不执行好；resume 有自己的 60 秒签名有效期（ADR-0029）
- 命令行超时提示写明「过期后不会再执行」，你需要查询后再决定是否重发

## 理由

- 超时之后的唯一确定结果应当是「没执行」，你重发一次就能看到真实结果
- `rule_add` 迟到：入场单、止损线、止盈线都是按写命令时的行情定的，闸门只看报价新不新鲜、限价偏离，不知道意图已经过时
- `rule_cancel` 迟到：入场单已成交时，取消规则会拿掉止损保护。你看到超时、以为规则还在，撤销却在之后不知情时生效，持仓就没有保护了。与 halt 不同，它并不总是减少风险，所以按「超时 = 没执行」处理
- 代价：入场单还没成交、你本想撤掉减少风险时，过期等于把这次撤销丢掉了，需要重发；超时提示会写明
