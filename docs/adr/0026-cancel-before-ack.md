# ADR-0026：订单确认之前收到的撤单

- **状态**：已定
- **日期**：2026-11-14
- **来源**：M4 计划（2026-11-14 你确认「等确认后自动发」）

## 决策

订单已经发往券商、但还没确认（本地 PENDING_NEW，或超时后的 UNKNOWN），这时收到撤单请求（命令行撤单，或 halt 撤全部挂单），怎么处理

## 取值

- 闸门照常受理（ADR-0016：只检查「订单属于本程序且处于活动状态」；PENDING_NEW 和 UNKNOWN 算活动状态），写审计
- OMS 不立即调用券商撤单，只在订单上记一个「待撤」标记（`cancel_pending`），并写一条 order_events
- 订单得到确认时（收到 ACK，即推送或轮询看到 `SUBMITTED`；或在 PENDING_NEW、UNKNOWN 时先收到成交），由 Executor 自动发出撤单，之后的流程与普通撤单相同（CANCEL_REQ → 等 `CANCELLED_*`）
- 订单在确认前就结束（被拒、或 UNKNOWN 判为 REJECTED、或在确认前全部成交）：清除标记，并在事件里写明原因
- 状态矩阵不变：「待撤」是订单上的附加标记，不是新状态；状态仍是 PENDING_NEW 或 UNKNOWN，直到确认后按 T27、T33 进入 PENDING_CANCEL
- 撤单被券商拒绝时，按 T38、T39 回到原状态并报警；不自动重试

## 理由

- 原状态机约定「未确认前不接受撤单」：券商还没给出订单号或状态时撤单，结果不可预测
- 但 halt 必须覆盖所有挂单，包括刚发出、还没确认的单。只撤已确认的单，会留下漏网之鱼
- 把撤单延到确认之后，既不违背原约定，也不会漏单
- 2026-11-13 两张单没撤掉，后来查明是账户限频（learnings「M3 › vendor 限频按账户计算」），与本 ADR 无关。本 ADR 针对的是 halt 时可能遇到的未确认订单
