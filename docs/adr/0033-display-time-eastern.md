# ADR-0033：给人看的时间一律用美东时间

- **状态**：已定（全局要求）
- **日期**：2026-11-16
- **来源**：你 2026-11-16 的要求；补充 ADR-0011

## 决策

时间在系统内部和对外展示时分别用什么时区

## 取值

- **内部一律 UTC**（ADR-0011 不变）：数据库、journal、kv、命令表、签名、探针与推送的录制文件
- **所有和人打交道的地方一律美东时间**（America/New_York，含夏令时），并标「（美东）」：邮件（标题和正文）、终端输出与报错提示、日志里给人看的时刻、CSV 报告、PROGRESS 等文档里记录的运行时刻
- 统一用 `mooapp.common.et_str()` 格式化（`YYYY-MM-DD HH:MM:SS（美东）`）；只有日期时用美东日期
- 价格展示用 `price_str()`：最多 4 位小数、至少 2 位
- 新写的展示代码不得直接输出 `isoformat()` 的 UTC 时间；评审和测试检查「+00:00」不出现在展示内容里

## 理由

交易时段、收盘时刻、心跳时刻都按美东定义；人在看邮件和终端时不应再换算时区。内部保持 UTC，避免夏令时切换出错（ADR-0011）。

## 已知待改

`dev/milestone_7` 分支（M7）的 `mooapp eod` 输出里，收盘价来源已是美东；其余展示随 M5、M7 合并时一起检查。
