# ADR-0025：本地日志先行（数据库不可用时的备份）

- **状态**：已定
- **日期**：2026-11-11
- **来源**：SPEC.md 第 9 节 Q22（2026-11-11 答复）

## 决策

数据库不可用时，撤单、halt 和审计怎么办

## 取值

- 每个写库事务提交前，先把内容写成本地 journal 文件 `var/journal/<env>/pending/<entry_id>.json`，写完 fsync，权限 600；提交成功后移到 `archive/YYYY-MM-DD/`。
- 库不可用时：闸门拒绝新单（读不到当日次数、持仓、亏损）；撤单和 halt 照常执行，审计与订单事件只写 journal。
- 程序启动和库恢复时，按写入顺序回放 `pending/`，按 `entry_id` 幂等；回放成功的移入归档，失败的保留并告警。回放完成之前，闸门不接受新单。
- journal 和归档按日志对待：不进 Git，账号只保留后 4 位，不含密码、DSN 等任何凭据。
- v1 不加密：加密要新增依赖，还要在 secrets 里放密钥，而 sandbox 读不到 secrets，SIMULATE 下就没法用。以后需要时另建 ADR。

## 理由

撤单和 halt 只会减少风险，不应因为数据库故障被拦住（ADR-0016）；先写 journal 能保证审计不丢。新单必须依赖库里的状态才能做风控判断，所以库不可用时一律拒绝。
