# ADR-0031：可卖数量以券商 can_sell_qty 为准，只再扣券商还不知道的本程序卖单

- **状态**：已定
- **日期**：2026-11-16
- **来源**：探针 P10d（learnings「M4 探针 P10」）；修复计划 1（2026-11-16 你选 A）；替代 M4 确认点 3 的卖出部分

## 决策

卖出前「还能卖多少」怎么算

## 取值

```
可卖 = min( can_sell_qty − 本程序未确认卖单剩余量 ,  持仓 qty − 本程序全部未完成卖单剩余量 )
```

- `can_sell_qty`、`qty`：券商持仓（vendor § Get Positions）
- 未确认 = 券商还不知道的状态：CREATED、PENDING_NEW、UNKNOWN（UNKNOWN 可能已到券商，按保守处理，可能少算，不会多算）
- 第一项：P10d 实测券商的 `can_sell_qty` 已扣除所有已确认的未成交卖单（包括 App 里下的），只需再扣券商还没算进去的本程序卖单
- 第二项是保底：OpenD 缓存或本程序 0.5 秒持仓缓存还没反映刚确认的卖单时，不超过「持仓减本程序全部卖单」
- 买入侧不变：券商总持仓 + 本程序未成交买单剩余量 + 本单 ≤ `max_position_qty`（M4 确认点 3 的买入部分）

## 理由

- 旧规则「`can_sell_qty` − 本程序未完成卖单剩余量」把已确认的卖单扣了两次：持仓 10、本程序已确认卖单 3（`can_sell_qty` 7）时再卖 7 会被错误拒绝
- 只用 `can_sell_qty` 会在券商尚未确认、缓存尚未刷新的窗口里卖超；模拟账户是保证金账户，卖超就是做空，违反 ADR-0002
- 两项取小，各情形都不会多算（见 `tests/unit/test_risk_rules.py` 的 ADR-0031 一节）
